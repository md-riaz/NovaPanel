# Installed firewall restoration policy

This internal, unwired adapter implements the installed-destination decision at base f1201d8ac96e19fbb05efe080b8926294df6ebd6. Canonical recovery and custody requirements remain in docs/spec/phases/phase-6.md. ConfinedRestore and private immutable custody remain unchanged.

Production admission is fixed to effective UID 0, /etc/ufw and /var/lib/novapanel/firewall/restore with private markers below restore. No directories are created or repaired. Only an unexported fixture opener substitutes roots and trusted owner. Every component is opened no-follow with safe normal ancestor permissions and trusted ownership. Installed rules may be 0755 directories; private restore and markers must be exact 0700. Both roots and markers are pinned and rechecked throughout effects.

Only the six canonical snapshotNames[4:] rule leaves are replaced. Existing destinations and .novapanel-next staging must be no-follow single-link regular trusted-owner GID-0 files, mode exactly 0600, 0640 or 0644. Missing destinations default to 0600. Preserve admitted final mode, never arbitrary snapshot metadata. Admit all finals/stages and marker final/stage before effects; reject inode substitutions before unlink/rename. Safe stale mutable staging is regenerated, unsafe staging is retained. Immutable custody staging remains refused.

Restore validates journal ID/digest/enabled binding and retained rule hashes using bounded offset-independent reads. It takes a fresh-open-description exclusive flock on the pinned private restore root, with cancellable waits. Lock order is journal, custody verification, installed root. Close must not race Restore. Trusted root must not concurrently replace admitted objects. This detects changes, not malicious-root interference or coordination with unrelated UFW administrators.

Each rule is staged exclusively at 0600, fully written, chmodded only on its new descriptor to the selected final mode, validated, file-synced, closed, renamed and directory-synced with identity checks. All six publications precede commands. Fixed injected argv is /usr/sbin/ufw --force enable then reload for previously enabled state, or disable only otherwise. Commands receive LC_ALL=C and a fixed PATH. Tests use fake Runner only, never host UFW. After commands, all six leaves are reopened and checked for exact bytes, modes, ownership and safe metadata, then file/directory-synced. Safe identical command replacements are admitted.

Only then publish private canonical version/id/snapshot_sha256/prior_enabled JSON through 0600 .next, file sync, rename and markers-directory sync. Conflicting markers refuse before effects. Matching markers never skip full restoration. Marker evidence does not reconcile SQLite or acknowledge journal state. Root checks surround commands and publications. Any failure returns error without rollback; interrupted reverting replays the whole same ID through FireVerified or RevertVerified after reopen, including visible ambiguous markers. Visible terminal reverted follows existing journal behavior, not another adapter replay.

Six file replacements and commands are not atomic. Private marker provisioning, helper/timer ownership, command child lifetime/cgroup isolation, capture/arm/full-set-apply serialization, migrations, startup/RPC/CLI reconciliation and confirmation delivery remain separate runtime work. Public apply remains unsupported. Disposable-VM UFW/systemd, reachability, process death and power-loss acceptance are not established by scratch tests.
