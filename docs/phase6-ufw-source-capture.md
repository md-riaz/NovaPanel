# UFW source capture policy

Delegated implementation-owner ruling, recorded before implementation. Based on canonical phase-6.md B-D7 and the closed immutable custody inventory at lines 168-216, this slice supplies real Ubuntu UFW source capture, not another restoration wrapper. Public apply remains unsupported.

- Production admission is hard-wired to `/etc/ufw` and UID 0. Tests substitute only the source directory and trusted owner through an unexported opener. No runtime path override or privileged command is added. Source directories need not be private custody directories: accept owner-readable/searchable directories with no group/other write or special mode bits, and only root/trusted-owner ancestors. Walk every component no-follow from `/`, pin source directory identity, and recheck it throughout capture. No sticky exception or chmod repair.
- Read only the six canonical names from that directory, not a wildcard. Each must be a trusted-owner, single-link regular file with no group/other write or special mode bits. Use no-follow/nonblocking descriptor opens and bounded reads. Extra UFW configuration files are expected and not captured. Missing IPv6 rules fail closed. Retain all six descriptors before commands, then re-open/revalidate identities and compare bytes after commands. Trusted root must not mutate the source during capture; these checks do not establish an atomic kernel/filesystem snapshot against malicious root.
- Use the injected Runner only with fixed absolute `/usr/sbin/ufw status numbered`, `/usr/sbin/iptables-save`, `/usr/sbin/ip6tables-save`. Set deterministic PATH and LC_ALL=C. PriorEnabled comes only from an exact first status line `Status: active` or `Status: inactive`, never from ufw.conf or a supplied bool. Repeat status numbered after captures and require byte equality. Unknown/localized/ambiguous status fails closed. All diagnostics must be nonempty and bounded. Set MaxOutput to the 4 MiB artifact limit plus one, then reject overflow, because Runner truncates rather than reports truncation. Check every command error, exit status and context. No shell or live commands in tests.
- Return the existing SnapshotInput only after all source checks and canonical total-size validation. The caller can publish through existing SnapshotCustody.Put, binding enabled state and exact inventory to the pending ID. Capture is a read operation and does not arm, mutate UFW, write custody, or consume a journal. Retry of immutable publication uses the original input; recapturing changed state for an already-used ID must be refused by Put, never overwrite custody. Tests exercise this explicitly.
- Production destination mapping, helper/timer/startup ownership and RPC integration are outside this bounded slice. Defaults/sysctl/hooks are not captured or restored. Real UFW/systemd, process-death and power-loss acceptance remain deferred final-product gates. No host service changes, publication or merge is authorized in this task.
