# Fresh-install execution domain ruling

This delegated ruling precedes implementation and narrows the first supported consumer to a reserved, fresh numeric site account which has never executed. It does not adopt an existing shared FPM account. The lifetime and offline trust contracts remain binding.

The agreed test seams are the sole `internal/exec` runner with a held typed cgroup descriptor, and a platform-owned closed-admission execution domain. Descriptor tests catch invalid/closed capabilities and placement refusal without fallback. Platform tests catch retained launch, cancel/drain ordering and recursive-empty refusal. Neither simulated control files nor ordinary runner tests prove kernel containment or IO retirement.

Use Linux `UseCgroupFD` with `CLONE_INTO_CGROUP` exclusively. Duplicate and retain the descriptor through child completion. Do not expose raw descriptor integers in RunOpts or fall back to migration. Keep the original no-shell runner, numeric credentials, replacement environment and bounded output semantics.

The platform module opens an existing empty root-controlled cgroup v2 domain beneath `/sys/fs/cgroup` with no-follow ancestor traversal. It does not create accounts, cgroups, services or mounts. Initial recursive emptiness excludes the agent and unrelated workloads at acquisition. Trusted root must exclude replacement, migration and outside launch throughout custody. The module admits only calls made through its runner, closes admission before cancellation, drains admitted calls, then writes cgroup.kill and observes recursive populated=0 within the caller's deadline. Failure leaves admission closed. Successful drain is process retirement only, never an all-writer or filesystem IO proof.

The jobs consumer must persist the original site/job/UID/GID/home and cgroup lifetime before first execution, hold ordered operation locks and trusted-root allocation/relocation exclusion, supply a bounded cleanup context independent of canceled work, and keep serving disabled on refusal. It must establish the never-executed/no-external-writer first-install premise before protected filesystem effects. Calling the process-drain method cannot establish that premise after site execution. A bootstrap child may create asynchronous IO; this module does not authorize protected publication after such a child without the separate backend retirement proof. No ConfigIsolation success callback or serving restart is installed by this slice. Dedicated per-site supervised FPM and durable admission/recovery integration remain subsequent consumers. Final VM acceptance remains deferred, not waived.
