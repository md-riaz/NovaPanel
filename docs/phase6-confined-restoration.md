# Confined verified-descriptor restoration policy

Implementation-owner ruling, recorded before production edits, based on phase-6.md B-D7, immutable custody and journal recovery contracts. This adds an internal, explicitly configured adapter only. No production paths, migration, startup/RPC wiring or phase completion are authorized.

- The preprovisioned confined destination root and its `ufw` and `markers` directories are same-effective-UID 0700. Reuse custody's strict no-follow root/ancestor checks, with no sticky exception. Pin all directory identities and recheck them before effects and after sync/commands. Root/agent UID remains trusted against concurrent mutation. Existing destination files must be single-link 0600 regular same-owner files; absent leaves are allowed. Unsupported layouts fail closed, never chmod/repaired.
- The only rule destinations are `ufw/after.rules`, `ufw/after6.rules`, `ufw/before.rules`, `ufw/before6.rules`, `ufw/user.rules`, `ufw/user6.rules`. Diagnostics and enabled bytes are not installed as rules. Consume borrowed verified file descriptors, never reopen custody paths. Recheck the canonical manifest binding and all six rule hashes before effects. Use bounded reads independent of descriptor offsets.
- Serialize the entire restore under a fresh flock on the pinned destination root, in addition to the caller's journal lock. Store lifetime flock is unchanged. Context cancellation retains journal reverting intent.
- Publish each rule by 0600 exclusive staging, file fsync, close, atomic rename and directory fsync. The six-file update is not atomic. An interruption requires replay of the entire same-ID operation. A validated stale single-link staging file may be removed and rewritten on retry; unsafe staging is refused. This policy differs deliberately from immutable custody, whose incomplete staging refusal is unchanged.
- After all six rule publications are durable, prior-enabled restoration runs fixed `/usr/sbin/ufw --force enable` then `/usr/sbin/ufw reload`. Prior-disabled restoration runs fixed `/usr/sbin/ufw disable`, with no reload or transient enable. Use only the existing injected argv Runner, check error and exit status, and supply no shell or dynamic arguments. A confined filesystem plus a fake runner proves ordering, not host UFW restoration. Real runners remain privileged and must not be supplied on the shared host.
- Only after successful commands, publish `markers/<id>.json` with canonical compact JSON fields `version`, `id`, `snapshot_sha256`, `prior_enabled`, then file and directory fsync. It is durable restoration evidence, separate from terminal audit/SQLite reconciliation. An existing marker must match the exact binding or refuse before effects. A matching marker never skips rule/command replay: journal intent, not marker presence, controls recovery. This avoids using visible post-rename/pre-sync evidence as an authorization to skip restoration. Interrupted same-ID retry republishes identical evidence and establishes durability before returning success.
- Failures in writes, commands, marker publication or identity checks return an error, so the journal retains reverting. No rollback across filesystem/UFW is claimed. Same-ID replay is the recovery mechanism. Real VM, process-death and power-loss acceptance remain deferred product-finish checks, not source implementation blockers.
